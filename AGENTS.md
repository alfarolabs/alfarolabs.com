# Alfaro Labs

Public website built with TanStack Start, React, TypeScript, and Vite for
Cloudflare Workers. Read `README.md` for development and publishing commands.

## Commands

- Use the Node version in `.node-version` and npm with `package-lock.json`.
- `npm ci` installs dependencies. In a fresh Amp orb, `.agents/setup` also
  installs the pinned Node toolchain; do not add installation work to a resume hook.
- `npm run check` runs TypeScript, the production build, and static smoke checks.
- `npm run smoke -- --url <origin>` checks a running site's pages, referenced
  assets, and missing-route 404. Use a local preview, not production, for validation.
- No separate test runner, linter, or formatter is configured. Match nearby code.

## Ownership and conventions

- `src/routes/` owns the pages and root document; `src/components/` owns shared UI.
- `src/content/index.ts` owns published copy, metadata, external links, and logo
  selection. Use its `published` values and `.toText()` in UI rather than inline
  copy. Load the `editing-site-content` skill for copy, metadata, brand, or booking changes.
- `src/styles/app.css` owns site styles. Use the existing components and CSS patterns.
- `src/routeTree.gen.ts` is generated by TanStack Router during dev/build. Do not
  edit it by hand. Do not edit generated `dist/` or `.wrangler/` output.
- `scripts/smoke.mjs` enforces copy rules and original brand-file hashes. Do not
  weaken checks or change expected hashes merely to make a change pass.
- Booking remains a placeholder until Carlos supplies a URL. Do not invent
  destinations, prices, testimonials, or proof of customer results.

## Preview and verification

- In an orb, use `amp orb services ensure` to start the declared production
  preview. After source changes, use `amp orb service restart preview` to rebuild.
  Share Amp's returned portal URL, not localhost or a direct sandbox hostname.
- Keep long-lived services under Amp's service supervisor, not background shell jobs.
- Run `npm run check` for application changes. Static smoke checks do not prove
  layout, hydration, or interactions: exercise affected flows in the browser.
- For visual changes, inspect desktop and mobile screenshots, including affected
  non-default states. For interaction changes, test pointer and keyboard behavior
  and inspect a recording. Use Amp's browser skill when available.
- Put review screenshots and recordings in `.amp/in/artifacts/`; keep transient
  debugging files elsewhere. Report commands, outcomes, and unverified behavior.

## Publishing and secrets

- Get Carlos's approval before pushing, opening or merging pull requests, or
  deploying. A push to `main` runs CI and deploys to both production domains;
  dispatching the workflow on `main` can also deploy. Do not deploy from a checkout.
- Local development needs no Cloudflare credentials, database, or seeded data.
  Keep secrets out of code, agent guidance, skills, logs, and screenshots.
- Keep project skills in `.agents/skills/<name>/SKILL.md`, with matching `name`
  and a specific trigger description. Reuse Amp's official skills for generic
  tasks; do not copy them here or override personal settings without a repo need.
